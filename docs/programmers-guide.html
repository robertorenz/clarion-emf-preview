ConceptsPages, twins and the text index

A Clarion report printed to PREVIEW leaves one metafile per page in a PrintPreviewFileQueue. With REPORT,…,UNICODE those files are enhanced metafiles (.emf, 600 dpi, one EMR_EXTTEXTOUTW per string); a classic report writes placeable .wmf files. EmfPreview never draws a page itself. It does three things with those files:

  1. Index them. EmfTextIndexClass.Build runs the shipped WMFDocumentParser over the queue with itself registered as both the narrow IReportGenerator and the wide IReportGeneratorW target. Every STRING, TEXT line, CHECK, RADIO and GROUP caption arrives as a USTRING with its rectangle in 1/1000 inch and goes into Texts; every page gets a row in Pages with its frame and offsets.
  2. Render a twin. To show a page, RenderPage plays the original metafile into a new EMF whose frame is exactly the zoomed display size, then draws the hits and marks over it with SetROP2(R2_MASKPEN) — the marker-pen effect that keeps black text black. The IMAGE control shows the twin, not the original.
  3. Map the mouse. Because the twin's natural size equals the display size, the IMAGE's scroll positions are pixels and a click converts to page mils with one division. ItemAt then finds the text item under the point.
!  page mils -> IMAGE pixels             IMAGE pixels -> page mils
Px = Mils * SELF.PxPerMil                Mils = (Px + ScrollPos) / SELF.PxPerMil

!  what the parser delivers for an EMF page, and what the index keeps
Left = F.Pos.Left - CurBoxL - CurOffX    ! CurOffX = (frame - printable) / 2, ~158 mils on a laser

The parser adds an offset that GDI playback does not

WMFParser reports EMF text positions including the printer’s physical offset — (frame − printable) / 2, about 158 mils on a typical laser — while PlayEnhMetaFile maps the frame as-is. ProbePage reads the offset from the header (szlDevice, szlMillimeters, rclFrame, with the same dpi snapping the parser uses) and AddText subtracts it, so index rectangles land on the displayed text. Do the same in any code that overlays parser coordinates on a played page.

Hits, marks and page marks

Three kinds of state, all kept on the previewer for the length of one Display:

  • Hits — the result of the last Find. One EmfMarkQueue row per match with the span (Start, Length in UTF-16 units) and its display rectangle. CurHit points at the framed one; Pages.Matches counts per page for the thumbnail labels. Capped at 5000.
  • Marks — the user's. A left click on a text line (ClickMarks) marks the whole item; Mark hits copies every hit as a mark. Painted in MarkColor, and printed when PrintMarks is on.
  • Page marks — Pages.Marked. Ctrl+M, the toolbar button, or a right click on a thumbnail. MarkedPageList turns them into '1,3,7-9', which is what Print marked hands to the ABC print loop as PagesToPrint.

How toRecipes

Derive the class

Every handler is VIRTUAL. Open runs after the window is built and the wheel hook installed; the Feq… members name every toolbar control so a derived class can drive them. Call PARENT in anything you override — the base handlers are where the ABC previewer's own logic is deliberately not run.

InvoicePreview CLASS(EmfPreviewClass),TYPE
Open             PROCEDURE(),VIRTUAL
TakeWheel        PROCEDURE(LONG Delta, LONG Keys, LONG XPix, LONG YPix),LONG,VIRTUAL
               END

InvoicePreview.Open PROCEDURE()
  CODE
  PARENT.Open()                                ! builds the window, hooks the wheel
  SELF.HintText = ' F3 jumps to the next invoice number'
  SELF.SearchText = U'Invoice No.'
  POST(EVENT:Accepted, SELF.FeqFind)           ! search as soon as the window is up

InvoicePreview.TakeWheel PROCEDURE(LONG Delta, LONG Keys, LONG XPix, LONG YPix)
  CODE
  IF BAND(Keys, MK_SHIFT)                      ! Shift+wheel flips pages
    SELF.GotoPage(SELF.CurrentPage + CHOOSE(Delta > 0, -1, 1))
    RETURN 1
  END
  RETURN PARENT.TakeWheel(Delta, Keys, XPix, YPix)

Remember the window, zoom and sidebar

INIMgr  INIClass
  CODE
  INIMgr.Init('.\MyApp.INI')
  Prev.SetINIManager(INIMgr)                   ! [_EmfPreview_]: window, Zoom, Sidebar
  IF Prev.Display() THEN Report{PROP:FlushPreview} = TRUE.

Nothing is remembered without an INI manager. With one, the section is [_EmfPreview_].

Fall back to the classic window

Set ClassicMode before Display and the object behaves exactly like its parent — every override starts with IF SELF.ClassicMode THEN RETURN PARENT.…. The per-report template extension does this when Use the EMF previewer is unticked.

Prev.ClassicMode = TRUE                       ! stock ABC preview window for this report

Use the text index without the window

EmfTextIndexClass is independent. Anything that wants the text of a printed report with its position — an audit dump, a table-of-contents builder, a “which page has this invoice” lookup — can use it alone:

Idx   EmfTextIndexClass
Out   ASCII,NAME(OutName)
Line  STRING(1024)
i     LONG

  CODE
  Idx.Init(GlobalErrors)
  IF Idx.Build(PgQ) <> Level:Benign THEN RETURN.
  CREATE(Out); OPEN(Out)
  LOOP i = 1 TO RECORDS(Idx.Texts)
    GET(Idx.Texts, i)
    Line = TOANSI(Idx.Texts.Text, 0FDE9h)      ! UTF-8: assign FIRST, then concatenate
    Out.Line = Idx.Texts.PageNo & '<9>' & Idx.Texts.Left & '<9>' & Idx.Texts.Top & '<9>' & CLIP(Line)
    ADD(Out)
  END
  CLOSE(Out)

Colours

All seven are COLORREF values, 00BBGGRR, the Clarion way round. The defaults are chosen so a hit reads as yellow marker on white paper and a mark as a light sky, and so the two thumbnail frames — blue for the current page, amber for a marked one — cannot be confused. Set them before Display; the template exposes every one on its Colors tab.

NotesWhat Clarion 12 Unicode does, and does not, do

Behaviour that belongs to the compiler, the runtime and the report engine rather than to this class — each one cost a debugging session, and each one shapes the code you will read in EmfPreview.clw.

The report engine

  • REPORT,…,UNICODE (the Unicode property in the report designer) prints wide text end to end and writes PREVIEW pages as enhanced metafiles. The probe confirmed 8 pages of 600-dpi EMF with the ' EMF' signature and about 3 000 records each. Non-UNICODE reports still write placeable .wmf.
  • Colour emoji are recorded as EMR_ALPHABLEND 32-bpp stamps in addition to the UTF-16 text run, so text search still finds them.
  • The shipped WMFDocumentParser has a complete EMF lane. Register a wide target with SetWideGenerator(IReportGeneratorW) and every text item arrives as a USTRING; the narrow IReportGenerator must still be supplied to Init. WideRun on the index tells you which lane delivered.
  • Parser coordinates for EMF pages include the printer's physical offset; GDI playback does not add it. See the note under Units.

The IMAGE control

  • An IMAGE shows a metafile at 96 dpi of its frame, and its HVSCROLL range is the picture's natural size. Rendering the twin with the display size as its frame is what makes scroll positions pixels.
  • The scroll bars only take effect once an image is loaded, and the range is only recomputed when the flags change — ShowPage switches PROP:HScroll / PROP:VScroll off and on again after every load, or a zoom change keeps the old range.
  • The control applies a WM_VSCROLL / SB_THUMBPOSITION lazily: ask for a position and GetScrollInfo still reports the old one for a while. ScrollLines remembers what it asked for (PendV, PendFromV) and continues from there when the control has not caught up, or two wheel notches in one tick land on the same spot.

The mouse wheel

Windows sends WM_MOUSEWHEEL to the control under the cursor (or with focus), and Clarion's control procedures swallow it — subclassing the frame with PROP:WndProc never sees the message. EmfPreview installs a per-thread WH_GETMESSAGE hook when the window opens (Open), routes wheel messages for any control of a registered preview window to that window's TakeWheel, and rewrites the message to WM_NULL when handled. Two details: test BAND(wParam, PM_REMOVE) rather than equality, because PeekMessage adds PM_QS_* bits; and the registry of open windows is plain module data behind a critical section — see the next point for why.

The runtime and the compiler

  • THREADed module-level data in a class module crashes at start-up in this build. The hook registry is a plain queue guarded by NewCriticalSection().
  • A class declared with DLL(_xDllMode_) whose define is missing from the project GPFs on first use (the VMT is garbage). EmfPreview therefore links unconditionally — MODULE('EmfPreview.CLW'),LINK('EmfPreview.CLW'), no DLL-mode parameters — and each module of a multi-DLL suite carries its own copy. An application that still references EmfPreviewClass after the template is removed compiles and runs.
  • TOANSI(u, 0FDE9h) (UTF-8) must be assigned to a STRING first. Inside a & concatenation the expression is evaluated wide and narrowed through the ANSI code page, and the UTF-8 is gone.
  • UPPER and INSTRING are Unicode-aware on USTRING, which is what makes the case-insensitive search a one-liner.
  • The compiler rejects LF-only source files. Keep .inc, .clw and .tpl as CRLF; test\crlf.py normalises them after a scripted edit.
  • Highlights use SetROP2(R2_MASKPEN) and a solid brush: the colour is ANDed over the page, so black stays black and white becomes the marker colour.

AppGen and the template

  • #SET on another template's prompt — here %PrintPreviewType, the ABC global Print Previewer class — is persisted into the .app by generation. The extension therefore puts the value back when it is disabled, and its Removing tab explains the order of operations.
  • Hand-written TXAs: the header order is VERSION, TODO, DICTIONARY, PROCEDURE; [ADDITION] blocks have no [END]; supply %ClassItem / %ClassLines for derived objects; progress controls need #ORIG(…). A TXA that gets one of these wrong imports without an error and silently drops the section.

NotesKnown limits

  • A hit's rectangle is measured with the item's font on the screen DC (GetTextExtentPoint32W); exotic fonts or justified TEXT controls can be a few pixels off.
  • Whole-word search treats only spaces as word boundaries.
  • Text marks live for the preview session; nothing persists them (the INI manager keeps window, zoom and sidebar only).
  • Search runs over the report's own pages; export still goes through the ABC target selector (Save as).
  • Index text is capped at 260 UTF-16 units per item, and a search at 5 000 hits.
