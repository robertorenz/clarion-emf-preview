Getting Started

Install it, preview a Unicode report by hand, then do the same thing from AppGen in four steps. Twenty minutes, Clarion 12 Unicode assumed.

3 files to install0 runtime files2 test programs

StartWhat this is

EmfPreview replaces the ABC PrintPreviewClass in a Clarion 12 Unicode application. The report engine is untouched: it still prints to PREVIEW page files, and the previewer still returns TRUE when the user wants the pages sent to the printer. What changes is the window — a thumbnail sidebar, full-text search over every page with the hits highlighted on the page, marker-pen text marks, page marks, zoom and fit modes, a mouse wheel that works, and printing only the marked pages or the pages with their marks baked in.

Template

One global extension swaps the previewer class for every report; an optional per-report extension sets the title, overrides options, or opts a report out.

↓  sets options on
EmfPreviewClass

Derived from PrintPreviewClass, so the report template's Previewer object, Display, Init and Kill keep their meaning. Hand-coded programs use it directly.

↓  is fed by
EmfTextIndexClass

Runs the shipped WMFDocumentParser over the page metafiles and keeps every text item with its page rectangle. Reusable on its own.

Clarion 12 Unicode only

The class relies on the Unicode report engine: REPORT,…,UNICODE writing .emf pages, USTRING, and the IReportGeneratorW wide lane of ABWMFPAR. None of that exists in Clarion 11 or the ANSI Clarion 12, and the include file refuses to compile there: EmfPreview_requires_Clarion_12_Unicode is the first error you would see.

StartInstalling

Run the installer from the repository folder. It copies three files and registers the template chain:

powershell -ExecutionPolicy Bypass -File install.ps1                      # C:\Clarion12unicode
powershell -ExecutionPolicy Bypass -File install.ps1 -ClarionRoot D:\C12U   # somewhere else
src\EmfPreview.inc   ->  <Clarion>\accessory\libsrc\win
src\EmfPreview.clw   ->  <Clarion>\accessory\libsrc\win
src\EmfPreview.tpl   ->  <Clarion>\accessory\template\win      then  ClarionCL -tr EmfPreview.tpl

Restart the IDE if it was open

The template registry is read at start-up. An IDE that was running during the install does not list EMF Unicode Previewer under Global Extensions until it is restarted, which looks exactly like the install not working.

Nothing to ship: the class is linked into the EXE (or into each DLL that uses it). There is no runtime file.

StartThe smallest preview, by hand

No templates. A Unicode report, 240 rows, and the previewer instead of the stock one:

  PROGRAM
  INCLUDE('KEYCODES.CLW'),ONCE
  INCLUDE('EQUATES.CLW'),ONCE
  INCLUDE('ERRORS.CLW'),ONCE
  INCLUDE('ABERROR.INC'),ONCE
  INCLUDE('ABREPORT.INC'),ONCE
  INCLUDE('EmfPreview.INC'),ONCE
  MAP
  END

GlobalErrors  ErrorClass
PgQ           PrintPreviewFileQueue         ! the report's page files land here
Prev          EmfPreviewClass
i             LONG
RowNo         LONG
RowName       USTRING(80)

Report REPORT,AT(500,1000,7500,9000),PRE(RPT),FONT('Segoe UI',10),THOUS, |
         PREVIEW(PgQ),UNICODE                ! UNICODE: wide text, .emf pages
         HEADER,AT(500,250,7500,700)
           STRING(U'Customers  Ω Ж 中 😀'),AT(0,0,7500,300),FONT(,14,,FONT:bold),CENTER
         END
Detail   DETAIL,AT(,,7500,300)
           STRING(@n5),AT(0,20,500,250),USE(RowNo),RIGHT
           STRING(@s80),AT(700,20,6000,250),USE(RowName)
         END
       END

  CODE
  GlobalErrors.Init()
  OPEN(Report)
  LOOP i = 1 TO 240
    RowNo   = i
    RowName = CHOOSE((i % 3) + 1, U'Ana Müller', U'Дмитрий Иванов', U'山田 太郎')
    PRINT(RPT:Detail)
  END
  ENDPAGE(Report)                            ! PgQ now holds one .emf per page

  Prev.Init(PgQ)
  Prev.Errors &= GlobalErrors
  Prev.Title = 'Customers - preview'
  IF Prev.Display()                          ! TRUE when the user chose Print
    Report{PROP:FlushPreview} = TRUE
  END
  Prev.Kill()
  CLOSE(Report)
  GlobalErrors.Kill()

Three lines that matter

PREVIEW(PgQ),UNICODE on the REPORT. Without UNICODE the pages are placeable .wmf files — still previewed and searched, but through the ANSI text lane, so 山田 in a name is lost to the code page.

Prev.Init(PgQ) hands over the page queue; Prev.Errors &= GlobalErrors is what the parser reports through.

IF Prev.Display() — the same contract as ABC: TRUE means print, and PROP:FlushPreview sends the pages. PagesToPrint is already filled when the user pressed Print marked.

StartThe same thing from AppGen

  1. Open the application, Global Properties → Extensions → Insert, pick EMF Unicode Previewer – Global (activate). Leave Replace the previewer in every report procedure ticked.
  2. Give each report the Unicode attribute in the report designer (the REPORT structure gets ,UNICODE). Classic reports keep working; they just lose non-ANSI characters in the text index.
  3. Generate and compile. Every report procedure's Previewer object is now an EmfPreviewClass — the extension sets the global Print Previewer class.
  4. Optional, per report: Extensions → EMF Unicode Previewer – Report options for a window title, local overrides, or to fall back to the classic window for that one report.

What the swap really is

The extension sets Global Properties → Classes → Report → Print Previewer to EmfPreviewClass, and Clarion stores that value in the .app. That is why removing the template has a procedure of its own — the Template Guide covers it, and so does the Removing tab on the extension itself.

StartThe tests

Two programs in the repository exercise the class, and both are useful as worked examples.

FolderWhat it is
test\EmfRptTestA hand-coded probe. EmfRptTest.exe prints an 8-page Unicode report (mixed scripts and emoji), dumps the metafile headers and the text index to pages\textindex.txt, then opens the previewer. EmfRptTest.exe autotest also drives it through search, marks, zoom, click-mark and the wheel hook by timer and writes screenshots to shots\.
testapp\EmfPrvTestAn AppGen application built headlessly: a .txd dictionary and a .txa with one ABC Report procedure carrying both extensions. ClarionCL -di, -ai, -ag, then MSBuild. removal.txa and disable.txa are the regression tests for taking the template out again.

Build either with the 32-bit MSBuild and the Clarion bin path:

C:\Windows\Microsoft.NET\Framework\v4.0.30319\MSBuild.exe EmfRptTest.cwproj /p:ClarionBinPath=C:\Clarion12unicode\bin /p:Configuration=Debug
